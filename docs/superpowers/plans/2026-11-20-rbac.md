# RBAC (admin / manager / member) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `is_superuser` with a `role` enum (admin / manager / member) enforced by permission dependencies on the backend and reflected on the frontend.

**Architecture:** `Role` lives on `User`; a static `ROLE_PERMISSIONS` map turns a role into a set of `Permission`s. `require_permission(...)` FastAPI dependencies gate endpoints using the user loaded from the DB on each request; `GET /users/me` returns the permissions so the frontend renders from the same source.

**Tech Stack:** FastAPI, SQLModel, Alembic, PostgreSQL, pytest; React, TanStack Router/Query, hey-api client, shadcn/ui, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-20-rbac-design.md`

## Global Constraints

- Role values are lower-case and equal their names: `admin`, `manager`, `member`. Postgres enum type name: `userrole`.
- Permission values: `users:read`, `users:manage`, `metrics:read`, `items:manage_all`.
- `member` → no permissions; `manager` → `users:read`, `metrics:read`; `admin` → all.
- No permissions or role in the JWT. Role and `is_active` are read from the DB on every request.
- `get_current_user` failures → 401 (invalid token, user not found, inactive). Missing permission → 403 with detail `"The user doesn't have enough privileges"`. Login with inactive account stays 400.
- New migration `down_revision = "fe56fa70289e"`.
- Do not stage `.env` or `.python-version`. Do not touch `.gitignore`.
- No new dependencies, no unrelated refactors, no visual polish.
- Backend commands run from `backend/`: tests `uv run bash scripts/test.sh`, lint `uv run bash scripts/lint.sh`. DB: `docker compose up -d db` from repo root.
- `scripts/test.sh` wipes all users; after a run, `uv run python app/initial_data.py` restores the admin.

## Review Focus

1. Admin `PATCH /users/{own_id}` with **unchanged** `role`/`is_active` (what a full-form submit sends) must succeed → test in Task 3.
2. `role: "admin"` in `POST /users/signup` or `PATCH /users/me` must be ignored, user stays member → test in Task 2.
3. Token of a user who was deleted must give 401, not 404/500 → test in Task 2.
4. Migration of an **inactive** superuser: becomes `admin` and stays inactive (no status change) → manual check in Task 2.
5. Manager `GET /users/{nonexistent_id}` → 404 (has `users:read`), member → 403 → test in Task 3.

```python
role_enum = sa.Enum("admin", "manager", "member", name="userrole")

def upgrade():
    role_enum.create(op.get_bind())
    op.add_column("user", sa.Column("role", role_enum, nullable=True, server_default="member"))
    op.execute("""UPDATE "user" SET role = 'admin' WHERE is_superuser""")
    op.execute("""UPDATE "user" SET role = 'member' WHERE role IS NULL""")
    op.alter_column("user", "role", nullable=False)
    op.drop_column("user", "is_superuser")

def downgrade():
    op.add_column("user", sa.Column("is_superuser", sa.Boolean(), nullable=False, server_default=sa.false()))
    op.execute("""UPDATE "user" SET is_superuser = true WHERE role = 'admin'""")
    op.drop_column("user", "role")
    role_enum.drop(op.get_bind())
```
